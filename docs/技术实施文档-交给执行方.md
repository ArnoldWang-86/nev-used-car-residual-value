蔚来（NIO）二手车业务需要一个**资产残值预测模型**。本项目的定位是**方法论验证 + 真实市场锚定**：

## 0.3 已确定的分析设计（不要改）

**主交叉设计：3 车系 × 2 车龄段 = 6 格**

- 车系：蔚来ES6、蔚来EC6、Model Y
- 车龄段：0-4年、4年+

**为什么只做 3 车系**：格数少 → 每格样本厚（最小 45 条）→ 单格精度 ±2.4pp。
若扩到 7 车系，最小格样本降到 20，精度降到 ±3.3pp，且多格不达标。

**为什么车龄只切 2 段**：3 段时「0-2年」段严重不足
（蔚来ES6 仅 7 条、Model Y 为 0 条），无法支撑推断。

## 1.4 ⚠️ 三个必须知道的陷阱

### 陷阱 1：`is_battery_swap` 与车系完全混淆

```
蔚来ES6: True=80, False=42
蔚来EC6: True=65, False=48
Model Y: True=0,  False=108   ← 特斯拉无换电，恒为 False
```

**后果**：在 3 车系合并的数据上，`is_battery_swap` 等价于「是不是蔚来」。
**做法**：**只在蔚来内部**（ES6 + EC6，共 235 条）比较换电 vs 非换电，不要在全局模型里放这个变量。

### 陷阱 2：车龄分箱太粗会引入箱内混淆

实测（同为「0-4年」段）：
```
蔚来EC6 车龄中位 27 个月
Model Y 车龄中位 39 个月   ← 差 12 个月
```
**后果**：只用 2 段因子做 ANOVA，会把「箱内车龄差异」算进「车系效应」。
**做法**：模型里**同时**放 `C(age_band)`（做交叉表）和 `age_months` 连续变量（控制箱内差异）。

### 陷阱 3：里程与指导价在车系间严重不均衡

| 车系 | 里程中位(0-4年) | 指导价中位 |
|---|---|---|
| 蔚来ES6 | 52,800 | 35.8 万 |
| 蔚来EC6 | 41,200 | 35.8 万 |
| **Model Y** | **116,400** | **29.2 万** |

Model Y 里程是蔚来的 2~3 倍，指导价低 6.6 万（低 18%）。
**后果**：不控制这两个变量，车系比较是有偏的。
**做法**：**必须**把 `mileage` 和 `guide_price` 放进模型。

### 陷阱 4：城市分布不均

```
苏州 183 条（24.5%）  广州 100  深圳 81  上海 41
成都 38  北京 32  石家庄 17  重庆 15  ...
```
**后果**：城市与车系可能相关，形成混淆。
**做法**：把 `city_name` 作为协变量控制；报告中声明样本城市分布。

### 陷阱 5：20 条燃油车混在数据里

`energy_type` 有 20 条为「燃油车」。
**做法**：**分析前剔除**，只保留 `energy_type == "新能源"`。

## 步骤 4：双因子 ANCOVA（核心分析）

**输出**：`output/04_ANCOVA.txt`

### 4.1 模型设定

```python
import statsmodels.formula.api as smf

model = smf.ols(
    "residual_rate ~ C(series) * C(age_band) "
    "+ age_months + mileage_wan + price_wan + C(city_name)",
    data=sub
).fit()

# 关键：用 Type II 平方和（因为设计不平衡）
import statsmodels.stats.anova as anova
table = anova.anova_lm(model, typ=2)
```

**为什么这样设定**：
- `C(series) * C(age_band)`：双因子 + 交互项（回答 Q2、Q3）
- `age_months`：连续车龄，控制「箱内车龄差异」
- `mileage_wan`、`price_wan`：**必须**，否则车系比较有偏
- `C(city_name)`：控制城市差异

### 4.2 必须报告的统计量

| 项目 | 说明 |
|---|---|
| 各效应的 F 值、p 值 | |
| **偏 η²（partial eta squared）** | 效应量，**必须报**，不能只看 p 值 |
| 样本量 n | |
| R²、调整 R² | |
| 回归系数表 | 含系数、标准误、p 值、95% CI |

**偏 η² 计算**（Type II ANOVA）：
```python
# 对每个效应：
partial_eta2 = SS_effect / (SS_effect + SS_residual)
```

**解读标准**：偏 η² ≈ 0.01 小、0.06 中、0.14 大。

### 4.3 ⚠️ 交互项的诚实处理

**已知**：交互效应可检出下限（MDE）约 **±6.9pp**（由最小格样本 45 计算）。

**计算口径（务必统一）**：
```
交互项检验实际是「两组差异之差」：
   ΔΔ = (μ_A1 − μ_A2) − (μ_B1 − μ_B2)
其标准误 = √(4·σ²/n)，故

MDE = (z_0.975 + z_0.80) × σ × √(4/n)
    = (1.96 + 0.842) × 0.0831 × √(4/45)
    = 2.802 × 0.0831 × 0.2981
    = 0.0694  →  ±6.9pp
```

⚠️ **不要和「单格均值的 CI 半宽」混淆**：n=45 时单格 CI 半宽为
`1.96 × 0.0831 / √45 = ±2.4pp`，那衡量的是单个格子的精度，
不是交互项的可检出能力。**两个数差近 3 倍，报告中必须区分。**

若交互项 p > 0.05：
> **不要写「无交互效应」**，要写：
> 「交互项未达显著（p=...），但在当前样本量下仅能检出 ≥6.9pp 的交互效应，
> 因此对折旧速度差异**只能给出方向性描述，不足以确认**。」

同时报告**描述性**的折旧幅度对比：
```
Model Y    : 0-4年残值 X → 4年+残值 Y，衰减 (X-Y)
蔚来ES6    : ...
蔚来EC6    : ...
```
并说明这些衰减幅度之差是否超过 **6.9pp**。

### 7.5.1 数据与特征集

**样本**：新能源 726 条（已剔除 20 条燃油车）

**⚠️ 字段覆盖限制**（决定了哪些模型可跑）：

| 字段 | 覆盖率 | 可用条数 |
|---|---|---|
| `age_months` | 99.9% | 725 |
| `mileage` | 100% | 726 |
| `guide_price` | 100% | 726 |
| `series` | 100% | 726 |
| `city_name` | 100% | 726 |
| `condition_grade` | 100% | 726 |
| `appearance_score` | 100% | 726 |
| `transfer_times` | 99.9% | 725 |

| `soh_pct` | **59.7%** | 434 |
| `battery_kwh` | **27.9%** | 203 |
| `is_battery_swap` | 100% | 726（但见下方陷阱）|

**两个特征集**（这是核心实验设计）：

```python
# F_base：公开数据集也有的特征（"通用市场信息"）
F_base = ["age_months", "mileage_wan", "price_wan",
          "C(series)", "C(city_name)", "C(condition_grade)"]

# F_batt：F_base + 只有新能源车才有的电池/车况特征
F_batt = F_base + ["soh_pct", "battery_kwh",
                   "is_battery_swap", "appearance_score", "claim_times"]
```

**⚠️ 两个必须处理的陷阱**：

1. **`is_battery_swap` 与 `series` 完全混淆**（Model Y 恒为 False）。
   若同时放入模型，树模型会把「是不是蔚来」当成一个强特征。
   **做法**：在 F_batt 里保留，但在 SHAP 解读时**必须说明它等价于品牌标识**，
   不能解释为「换电技术提升了残值」。

2. **`soh_pct` 与 `battery_kwh` 缺失严重**。
   若直接 `dropna()`，样本从 726 掉到约 190 条。
   **做法**：
   - 主实验：用**全样本 + 缺失指示变量**（`soh_pct` 缺失填中位数，另加 `soh_is_missing` 哑变量）
   - 辅助实验：在 `soh_pct` 非空的 434 条子集上重跑，验证结论一致性

### 7.5.2 交叉验证（关键，做错会得到虚高结果）

**必须用 GroupKFold，按 `series` 分组**：

```python
from sklearn.model_selection import GroupKFold, cross_val_score
cv = GroupKFold(n_splits=5)
scores = cross_val_score(model, X, y, groups=df["series"], cv=cv,
                         scoring="neg_mean_absolute_error")
```

**为什么**：同车系的车源高度相似，若跨训练/验证集，
模型只需"认出车系"就能预测，得到虚高的 R²——**这是数据泄漏，不是预测能力**。

**⚠️ 必做的反例演示**（这一步很重要，是方法论亮点）：

```python
# 错误做法：随机 KFold
from sklearn.model_selection import KFold
cv_wrong = KFold(n_splits=5, shuffle=True, random_state=42)

# 正确做法：GroupKFold
cv_right = GroupKFold(n_splits=5)
```

**报告两者差距**。预期随机 KFold 的 R² 显著高于 GroupKFold。
把这个差距写进报告，作为「数据泄漏有多大」的量化证据。

**超参调优**：用 `GridSearchCV` + 同样的 `GroupKFold`（不要用随机 KFold 调参）。
树模型搜索空间建议：
```python
param_grid = {
    "n_estimators": [100, 300, 500],
    "max_depth": [3, 5, 8, None],
    "min_samples_leaf": [1, 3, 5, 10],   # 小样本必须调这个，防过拟合
    "learning_rate": [0.03, 0.05, 0.1],  # 仅 GBDT/XGB/LGBM
}
```

**小样本警告**：726 条 + 5 折 → 训练集约 580 条。
**必须把 `min_samples_leaf` / `min_child_samples` 调大**（≥5），否则树模型必然过拟合。

**输出表格**：

| 实验 | 特征数 | n | MAE | R² | 较 E1 的 MAE 降幅 |
|---|---|---|---|---|---|

### 7.5.5 学习曲线（回答"还需要多少数据"）

**做法**：

```python
from sklearn.model_selection import learning_curve
train_sizes, train_scores, val_scores = learning_curve(
    model, X, y, groups=df["series"],
    cv=GroupKFold(n_splits=5),
    train_sizes=np.linspace(0.2, 1.0, 8),
    scoring="neg_mean_absolute_error"
)
```

**画出**：横轴样本量，纵轴 MAE（训练集与验证集两条线）。

**判读规则**（必须按此写结论）：
- 验证线**仍在下降** → **数据不足，加数据仍能提升** → 应给出「预估需要多少条才收敛」
- 验证线**已趋平** → 已达当前特征集的信息上限 → 加数据收益有限，应改特征或改问题
- 两线**间距大** → 过拟合 → 需加正则化或减特征

**这一项直接支撑采集决策**，是本步骤对业务最有价值的输出。

### 7.5.7 ⚠️ 预期结论（不要因为"分数低"就认为失败）

**必须预先知道可能出现的三种结果，并正确解读**：

**结果 A：树模型跑不过 Ridge（很可能）**
> 726 条对 boosting 模型偏少，且真实关系接近线性（车龄解释 82% 方差）。
> **正确表述**：「在小样本、强线性主效应的场景下，带正则的线性模型
> 与树模型预测力相当，且更稳定、更可解释。
> 这与公开数据集线上的发现一致（该线上树模型无法外推，Ridge 最稳）。」
> **这是结论，不是失败。**

**结果 B：全部模型 R² 很低甚至为负**
> 残值率受车况、配置、地域偏好等大量未观测因素影响，726 条能捕获的有限。
> **正确表述**：「R² 低反映的是数据的信息上限，而非建模失败。
> 学习曲线显示验证误差仍在下降，说明**增加样本量仍能提升**。」
> **并给出需要多少条数据的预估。**

**结果 C：GroupKFold 比随机 KFold 差很多**
> 这是**预期且正确**的。
> **正确表述**：「随机切分导致同车系车源跨训练/验证集，产生数据泄漏，
> R² 虚高 XX 个百分点。采用 GroupKFold 后的数值才是可信的泛化性能。」
> **这个对比本身就是交付价值。**

**❌ 禁止**：
- 挑一个随机种子的好结果上报
- 只说"模型效果不错"而隐藏低分
- 用测试集调参后再报测试集成绩（必须留出独立测试集或全部用 CV）

# 3. 硬性规范

## 3.1 统计报告规范

**每一条统计结论必须包含**：
- 样本量 n
- 点估计 + 95% 置信区间
- 效应量（不只 p 值）

**禁止**：
- ❌ 只报 p 值不报效应量
- ❌ 在 n < 20 的格上做显著性检验
- ❌ 把 p > 0.05 写成"证明无效应"
- ❌ 用"显著提升/大幅改善"等无量化表述

## 3.2 精度参照表（用于判断结论可靠性）

基于 **σ_within = 0.0831**（3 车系子集实测，控制车龄段后）。

### 表 A · 单格均值的 95% CI 半宽

公式：`1.96 × 0.0831 / √n`

| 样本量 n | CI 半宽 |
|---|---|
| 20 | ±3.6pp |
| 30 | ±3.0pp |
| **45** | **±2.4pp** ← 本项目最小格 |
| 50 | ±2.3pp |
| 65 | ±2.0pp |
| 100 | ±1.6pp |

### 表 B · 交互项可检出下限（MDE）

公式：`(1.96 + 0.842) × 0.0831 × √(4/n)`

| 最小格 n | 可检出交互效应 |
|---|---|
| 45 | ±6.9pp ← 本项目 |
| 50 | ±6.6pp |
| 65 | ±5.8pp |
| 100 | ±4.7pp |

> ⚠️ **表 A 与表 B 差约 3 倍，报告中必须区分**：
> 表 A 衡量「单个格子估得多准」，表 B 衡量「能否发现交互效应」。
> 交互项实质是「两组差异之差」，标准误是单组差异的 √2 倍，
> 且需同时满足 α 与 β 两个条件，故 MDE 远大于单格 CI 半宽。

**判据**：只有当效应量 > 2 × CI 半宽时，才可称"存在差异"。

## 3.4 已知的实测交叉表数值（供核对）

> 同为新能源口径（726 条）

**原始中位数（未控制任何协变量）**：

**初步观察**：Model Y 残值率高于蔚来两车，且**衰减幅度明显更小**

**但不得据此直接下结论，有两个问题**：

1. **未控制里程**：Model Y 里程是蔚来的 2~3 倍
   （0-4年段中位 116,400 vs 41,200~52,800 km）。

2. **未控制指导价**：Model Y 指导价中位 29.2 万，蔚来 35.8 万，低 18%。

交互差异（20.1 − 11.8 = **8.3pp**）虽然超过可检出下限，
但**必须经 ANCOVA 检验确认**，不能靠原始中位数相减来判断。

```
                                    步骤5 全样本回归
                                          │
                                          ↓
                                    步骤6 稳健性检验
                                          │
                                          ↓
                          ┌───────────────┴───────────────┐
                          ↓                               ↓
                    步骤7 可视化              步骤7.5 机器学习（预测建模核心）

```

**两个核心步骤都要做，不可偏废**：
- **步骤 4（ANCOVA）** 回答「车系之间**有没有**差异」→ 输出 p 值、偏 η²、调整均值
- **步骤 7.5（机器学习）** 回答「残值**能预测多准**」→ 输出样本外 MAE / R²、学习曲线

**两个检查点**：

# 6. 遇到问题时的排查顺序

| 症状 | 排查 |
|---|---|
| 中文输出乱码/报错 | 加 `sys.stdout.reconfigure(encoding="utf-8")` |
| 图表中文显示方框 | 设置 `font.sans-serif = ["Microsoft YaHei"]` |

| **ML 模型 R² 很高（>0.9）** | **可疑！先检查是否用了随机 KFold 而非 GroupKFold（数据泄漏）** |
| **ML 模型 R² 很低（<0.3）** | 正常，见 7.5.7 节；重点报学习曲线而非分数 |

| **F_batt 相对 F_base 无提升** | 可能真实，见 7.5.3；必须报 bootstrap CI 并如实说明 |

本项目有**两条并行的方法论线**，最终报告必须体现两者的分工：

| | 统计推断（步骤 3-6） | 预测建模（步骤 7.5） |
